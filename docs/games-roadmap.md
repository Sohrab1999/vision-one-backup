## ۰. خلاصه اجرایی

آزمایشگاه بازی‌ها با **۱۵ بازی فعال** (۵ بازی پایه فاز ۳ + ۱۰ بازی فاز ۴/۵) به بلوغ ساختاری رسیده است: ثبت امتیاز سروری، XP، رکورد شخصی، TTS، اتصال به مرور هوشمند (SRS) و دسترس‌پذیری پایه از قبل وجود دارد. اما ممیزی کد (بخش ۳) نشان می‌دهد لایهٔ **«حس بازی» (Game Feel)** و **«مدیریت جلسه»** تقریباً غایب است: هیچ بازی‌ای صدا ندارد، هیچ بازی‌ای توقف/ادامه (Pause) ندارد، خروج تصادفی بدون هشدار پیشرفت را نابود می‌کند و تایمرها در تب مخفی به کار ادامه می‌دهند.

این سند ارتقا را در **۷ فاز (G0 تا G6)** با ۴۲ کارِ شماره‌دار، اولویت‌دار (P0/P1/P2) و دارای معیار پذیرش قابل تست تعریف می‌کند. ستون فقرات برنامه، ساخت **«کیت بازی» (GameKit v2)** است تا به‌جای ۱۵ بار تکرار، یک‌بار زیرساخت ساخته شود و همهٔ بازی‌ها روی آن سوار شوند.

> **قانون طلایی این نقشه راه:** هیچ بازی‌ای «فقط بازی» نیست؛ هر دور بازی باید یا یک واژه را تثبیت کند، یا داده‌ای به SRS بدهد، یا انگیزه‌ای قابل‌اندازه‌گیری بسازد.

## ۲. استانداردهای مرجع (قرارداد اجباری همهٔ فازها)

هر کارِ این نقشه راه باید با این ۸ استاندارد سازگار باشد؛ بازبینی کد بدون این چک‌لیست پذیرفته نمی‌شود:

1. **دسترس‌پذیری — WCAG 2.2 AA:** ادامهٔ الگوی اعلام‌شدنی محلی `role="status" aria-live="polite"` (مستند در `games/shared.ts`)؛ هر بازخورد صوتی/رنگی باید متن اعلام‌شدنی معادل داشته باشد (قانون «سه‌کاناله: صدا + رنگ + متن»). هدف لمسی حداقل ۴۴px.
2. **Game Feel (قانون جویس ۱۰ثانیه‌ای):** هر رویداد مهم بازی (پاسخ درست/غلط، رکورد، پایان) باید حداکثر ۱۰۰ms پس از اقدام کاربر، هم‌زمان سه بازخورد بدهد: **صدا + حرکت/رنگ + عدد/متن**. بدون صدا، حرکت باید جایگزین تقویت‌شده داشته باشد (reduced-motion).
3. **صدا — Web Audio API:** صدا فقط با WebAudio (نه `<audio>` per-clip) و **آپ‌لاک پس از اولین ژست کاربر** (سیاست autoplay مرورگرها). حالت بی‌صدا (mute) به‌صورت سراسری در استور + رعایت `navigator.userActivation`.
4. **لرزش — Vibration API:** فقط به‌عنوان بهبود تدریجی (progressive enhancement) با گارد `navigator.vibrate?.()` و زیر همان کلید mute صدا؛ هرگز در iOS Safari (پشتیبانی نمی‌شود) fallback خطا ندهد.
5. **چرخهٔ حیات صفحه — Page Lifecycle:** هر تایمر/رAF در `visibilitychange→hidden` باید متوقف و در `visible` از سر گرفته شود؛ `pageshow` با `persisted` (بازگشت از bfcache) هم باید مدیریت شود.
6. **بودجهٔ کارایی:** LCP < 2500ms · INP < 200ms · CLS < 0.1 (بودجهٔ موجود پروژه) + دو بودجهٔ جدید: **chunk هر بازی سبک ≤ ۳۰KB gzip** و مجموع سه‌بعدی (three + R3F) ≤ ۷۰۰KB gzip؛ انتقال ۱۴ بازی از باندل اصلی به lazy (G1-04).
7. **حریم خصوصی نوجوان:** هیچ رویداد تله‌متری جدیدی PII ندارد؛ قرارداد `/api/client-log` (فقط extra تخت ≤ ۵ کلید رشته‌ای) رعایت شود؛ پیشرفت بازی محلی می‌ماند و فقط با رضایت (پشتیبان اختیاری موجود) بالا می‌رود.
8. **آفلاین‌فرست:** همهٔ قابلیت‌های جدید بازی باید بدون شبکه کار کنند؛ همگام‌سازی فقط از مسیر صف موجود `src/lib/offline-queue.ts` (سقف ۲۰۰) — مسیر fetch مستقیم جدید ممنوع.

## ۴. معماری هدف: کیت بازی (GameKit v2)

یک لایهٔ مشترک جدید در `src/components/book/games/kit/` که ۱۵ بازی روی آن سوار می‌شوند. اصل طراحی: **opt-in تدریجی** — هیچ بازی‌ای یک‌جا بازنویسی نمی‌شود؛ هر بازی فاز G2 را جداگانه مهاجرت می‌کند.

```
games/
├─ kit/
│  ├─ sound-engine.ts        ← WebAudio سینتِتیک (بدون فایل صوتی؛ حجم ~۲KB)، mute-store، آپ‌لاک ژست
│  ├─ haptics.ts             ← نذر لرزش الگو-دار (درست/غلط/رکورد) با گارد پشتیبانی
│  ├─ use-pause.ts           ← هوک Pause: تایمر امن + visibilitychange + bfcache + دیالوگ
│  ├─ exit-guard.tsx         ← Dialog «خروج از بازی؟» + آزادسازی رویداد + نگه‌داشت پیشرفت draft
│  ├─ game-shell.tsx         ← قاب استاندارد بازی: هدر (نام/توقف/خروج) + سربرگ راهنما + فوتر آف‌لاین
│  ├─ result-screen.tsx      ← صفحهٔ پایان استاندارد: ستاره، آمار، رکورد، دکمه‌های بازی مجدد/اشتراک/مرور خطاها
│  ├─ difficulty.ts          ← پیش‌تنظیم‌های ۳سطحی (آسان/معمولی/سخت) per-game با فرمول امتیاز
│  ├─ tutorial-overlay.tsx   ← اورلی ۳-گامی تعاملی (یک‌بار در localStorage، دکمهٔ «بازآموزی»)
│  ├─ combo-engine.ts        ← موتور کمبو/استریک/ضریب مشترک (یک فرمول برای همه)
│  └─ telemetry.ts           ← رویدادهای استاندارد session_start/end/abandon + رعایت قرارداد client-log
└─ … (۱۵ بازی فعلی دست‌نخورده تا فاز G2)
```

**اصل وابستگی:** بازی ← GameKit ← استورهای موجود (`xp-store`, `srs-store`, `streak-store`, `goal-store`, `offline-queue`). GameKit هرگز مستقیم API صدا نمی‌زند؛ ثبت سروری همچنان فقط از `shared.ts/saveAttempt` می‌گذرد (تک‌مسیر بودن داده حفظ شود).
