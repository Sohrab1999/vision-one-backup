## §۱) متن عین مالک (عیناً)

### الزام حیاتی: پایداری کامل پروژه و بازیابی پس از Reset یا حذف Sandbox

پس از هر تغییر، باید وضعیت پایدار پروژه را به‌گونه‌ای ثبت و در Git Commit و Remote Push کنی که حتی در صورت Reset کامل، حذف یا نابودی Sandbox فعلی، هیچ‌یک از تغییرات، تصمیم‌ها، مستندات یا پیشرفت‌های تأییدشدهٔ پروژه از دست نرود و پروژه دچار عقب‌گرد نشود.

الزامات اجباری:

1. فایل `docs/SNAPSHOT.md` را پس از هر گام به‌صورت کامل، دقیق و متناسب با وضعیت واقعی پروژه به‌روزرسانی کن؛ نه صرفاً با افزودن چند خط خلاصه.
2. Snapshot باید وضعیت واقعی و قابل‌بازیابی پروژه را ثبت کند؛ از جمله معماری، قابلیت‌های پیاده‌سازی‌شده، فایل‌ها و مسیرهای دقیق، تصمیم‌های محصولی، قراردادهای فنی، ساختار داده، وابستگی‌ها، وضعیت تست‌ها، محدودیت‌ها، کارهای تکمیل‌شده و باقی‌مانده و گام بعدی مجاز.
3. تمام اسناد مرجع مرتبط، تصمیم‌نامه‌ها، Roadmap جامع و `worklog.md` را نیز به‌روزرسانی کن تا هیچ تصمیم یا تغییر مهمی فقط در حافظهٔ مکالمه، خروجی چت، فایل موقت یا Sandbox باقی نماند.
4. وضعیت Git را به‌عنوان بخشی از Snapshot ثبت کن: Branch، Commit SHA، وضعیت Working Tree، Remote و SHA تأییدشدهٔ Remote.
5. پیش از Commit، بررسی کن تمام تغییرات ضروری و مستندات پایدار در Git قرار گرفته باشند و هیچ فایل ضروری فقط در محیط موقت باقی نمانده باشد.
6. پس از Commit، Push به Remote را تأیید کن و با `git ls-remote` برابری SHA محلی و Remote را اثبات کن.
7. Snapshot و اسناد باید به‌اندازه‌ای دقیق باشند که یک محیط تازه، بدون دسترسی به Sandbox قبلی و بدون اتکا به تاریخچهٔ چت، بتواند صرفاً با Clone کردن Repository و مطالعهٔ اسناد، وضعیت پروژه را دقیقاً بازیابی و توسعه را از آخرین نقطهٔ تأییدشده ادامه دهد.
8. اگر هر اطلاعات ضروری برای بازیابی در Repository قابل‌ثبت نیست، آن را صریحاً شناسایی و علت و روش بازیابی‌اش را مستند کن؛ هرگز ادعای بازیابی کامل نکن.
9. هیچ تغییر تأییدشده‌ای را به دلیل Reset، پاک‌سازی Sandbox، پایان نشست یا جابه‌جایی محیط از دست نده.
10. این الزام در تمام گام‌های بعدی نیز پابرجاست و نباید به‌عنوان یک اقدام یک‌باره تلقی شود.

**معیار پذیرش:** اگر Sandbox فعلی همین لحظه کاملاً حذف شود، پروژه باید با Clone کردن Remote و مطالعهٔ Repository و اسناد پایدار، بدون از دست رفتن هیچ پیشرفت تأییدشده‌ای قابل بازیابی باشد.

صرفاً نوشتن Snapshot کافی نیست؛ Snapshot، اسناد مرتبط، Commit و Push موفق باید همگی با شواهد قابل‌بررسی تأیید شوند.
