## ۳) زنجیرهٔ بارگذاری و Root Cause

مسیر: انتخاب کتاب (قفسه/دروپ‌داون) → `setBook` → `book-storage` → `BookProvider` (effect) → `requestBookData` → `loadBookData` (registry — dynamic import چانک) → کش ماژولی `book-data-store` → رندر. `data = null` تا رسیدن چانک → اسکلت `BookDataLoading`.

### علت ریشه‌ای (تأییدشده — سطح کد)

در کدِ پیش از رفع، `requestBookData` شکست import را **فقط در کنسول لاگ می‌کرد** (`catch → console.error`)؛ نه خطا ثبت می‌شد، نه به UI اعلام، نه timeout داشت. نتیجه: با هر شکست واقعی (ChunkLoadError/شبکه/سرور مرده/چانکِ نسخهٔ قدیمی)، `data` برای همیشه null می‌ماند → **اسکلت «در حال باز کردن جزوه…» بی‌پایان** = دقیقاً علامت گزارش کاربر. بازتولید: اسکرین‌شات قبلِ جلسهٔ پیشین (`qa-shots/p0bl1-before-infinite-skeleton-1440.png` — صفحهٔ گیرکرده حین خاموشی واقعی سرور) + ردیابی کد در HEAD.

### محرک (سطح محیط — چرا کاربر آن را دید)

- **H-A — مرگ فرایند سرور dev در سندباکس** (الگوی مستند SNAPSHOT §۹): در این جلسه **۵+ بار مشاهده شد** (سرور بین فراخوانی‌ها کشته می‌شد؛ curl = `000`). کاربرِ بدون کشِ کامل با سرور مرده → شکست چانک → اسکلت بی‌پایانِ بدون رفع.
- **Stale shell پس از راه‌اندازی دوبارهٔ سرور:** آزمون شد — shell قدیمی URLهای چانک نسخهٔ قبلی را درخواست می‌کند و retry هم همان URL کهنه را می‌زند (۴۰۴ تکراری)؛ راهحل درست «بارگذاری دوبارهٔ صفحه» است که در UI فراهم شد.
- تمرکز مأموریت روی علامت اصلی (اسکلت بی‌پایان) بود؛ تشخیص محیطی H-A با شبیه‌سازی واقعی تأیید شد و الگوی عملیاتی (`scripts/revive-server.sh`) پابرجاست.

## ۴) اصلاح حداقلی (دو فایل — خارج از مسیر سالم صفر تغییر)

### `src/lib/book-data-store.ts`
- ثبت خطای آخرین تلاش هر کتاب (`errors` Map) + `emit` به شنوندگان.
- سقف انتظار `BOOK_DATA_TIMEOUT_MS = 60_000` (سنجش: کامپایل سرد بزرگ‌ترین جزوه‌ها < ۶۰ث) — انتظار معلق بی‌نهایت ناممکن شد.
- `retryBookData(id)` امن: فقط وقتی تلاش جاری تمام شده؛ خطا پاک و درخواست تازه.
- موفقیتِ دیرهنگام پس از timeout هم کش و emit می‌شود (بازیابی خودکار UI بدون رفرش — race بی‌ضرر و بدون duplicated data).
- خروجی null از registry (شکست چانک) = خطای صریح، نه سکوت.

### `src/app/page.tsx`
- شاخهٔ خطا در `BookDataLoading` (`role="alert"`، تم کهربایی، بدون `data-boot-loading` تا گارد بوت پرچم را بردارد): پیام صادقانه («بارگذاری … ناموفق بود» + «پیشرفت و داده‌های شما سالم است») + دو دکمهٔ **«تلاش دوباره»** (retryBookData) و **«بارگذاری دوبارهٔ صفحه»** (برای stale shell).
- گرم‌کردن chunk خانه: `.catch(() => {})` — جلوگیری از unhandled rejection در آفلاین/سرور مرده (بهینه‌سازی بماند، دروغ نگوید).

**دست‌نخورده‌ها (تعهد §۴ مأموریت):** registry/LOADERS، `sw.js` و strategy کش، دادهٔ کتاب‌ها، API/schema، hook، ناوبری و رفتار عادی بارگذاری — هیچ معماری جدیدی ساخته نشد.

## ۷) محدودیت‌ها و یادداشت‌های باقی‌مانده

- retry در «stale shell» (URL چانکِ نسخهٔ قدیمی پس از راه‌اندازی دوبارهٔ سرور) بی‌اثر است — طراحی: همان دکمهٔ «بارگذاری دوبارهٔ صفحه» راه‌حل درست است و در پیام خطا به آن هدایت می‌شود.
- ناپایداری جلسهٔ `agent-browser` هنگام چرخهٔ مرگ/احیای سرور چندبار مشاهده شد (ابزار آزمون، نه اپ) — علامت در جدول «سانحهٔ ابزاری» ثبت شد؛ هیچ تغییری در اپ برایش لازم نشد.
- علت محیطی H-A (کشتن فرایندهای پس‌زمینه توسط سندباکس) خارج از اختیار اپ است؛ کاهش‌دهنده‌های عملیاتی (hook پُست‌کامیت + `revive-server.sh` + تسک دوره‌ای) پابرجایند.
- `pkill -f chrome` در `revive-server.sh` مرورگر آزمون را هم می‌بندد (پاک‌سازی حافظه) — رفتار مستند ابزاری؛ تغییرش خارج از محدودهٔ این مأموریت بود.
