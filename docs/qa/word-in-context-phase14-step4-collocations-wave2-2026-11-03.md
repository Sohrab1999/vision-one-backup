## ۴) منطق دقیق ورود Collocations (توسعهٔ محدود و داده‌محور)

### ۴-۱) سرویس — سه تغییر جراحی

1. **دامنه به‌صورت داده (نه hardcode پراکنده):** `WAVE2_UNGRADED_BOOKS: BookId[] = ["collocations"]` — تنها نقطهٔ تعریف منابع مکمل؛ افزودن/حذف آینده فقط همین یک خط را تغییر می‌دهد (و فقط با تصمیم مالک).
2. **ترتیب کامل موج ۲ — تابع جدید `wave2Order(active)`:** `[...gradedWave2Order(active), ...WAVE2_UNGRADED_BOOKS.filter(id => id !== active)]` — یعنی ① پایه‌دارهای ۷→۱۲ منهای فعال با |Δپایه| صعودی + tie-breaker پایهٔ صعودی (**بایت‌به‌بایت گام ۲**) ② سپس منبع مکمل در انتها — مطابق قاعدهٔ تعیین‌تکلیف‌شدهٔ F-CV-1: `proximityRank` برای بی‌پایه‌ها = `100 + index(UNGRADED_ORDER)` و `UNGRADED_ORDER[0] = "collocations"` (`cross-book-vocab.ts:65-75`). **ترتیب نمایش Collocations از قرارداد مصوب استخراج شد** (گزارش ارزیابی گام ۳ §۶-۴ و §۷: «بی‌پایه‌ها پس از همهٔ پایه‌دارها») — نه تصمیم اختراعی.
3. **اتصال نقطه‌ای:** در `lookupSentencesWithStatus` فقط یک خط (`gradedWave2Order` → `wave2Order`)؛ ادغام/حذف تکرار (کلید ۴جزئی با bookId)/سقف ۱۲ سطح سکشن/degraded — **بایت‌به‌بایت گام ۲**.

`gradedWave2Order` عمداً دست‌نخورده ماند (فقط توضیحات) تا رفتار گام ۲ و اسکریپت‌های رگرسیون مستقل بمانند.

## ۱۱) محدودیت‌ها و تست‌های NOT RUN

2. **NOT RUN — پیش‌بارگذاری آفلاین چانک collo بدون اولین miss:** خارج از مجوز (نیاز به تغییر پیاده‌سازی/آفلاین-فیرست جدید) — محدودیت مستند C-5 گام ۲ همچنان برقرار است.
3. **کیفیت معنایی ترجمه‌های ماشینی fa collo** بدون بازخوانی انسانی است (محدودیت ثبت‌شدهٔ گام ۳ §۱۰-۲ — ساختار D7 فقط صحت ساختاری را تضمین می‌کند).
4. **زیرنویس حالت فعال-بی‌پایه + collo-present:** در اسکن فعلی چنین ترکیبی مرئی نشد (فعال hill → collo فقط در انتها و همراه پایه‌دارها — همان حالت ۱)؛ نگارش هر دو حالت در کد هست و سرویس‌سطح پوشش داده شده.
5. آمار گام ۳ با «سمانتیک موتور» بود؛ اعداد مرجع طراحی همچنان پیوست ب-۲ سند UX است.

## ۱۲) وضعیت نهایی Git و Remote

> SHAها پس از commit همین سند با `git log -1` و `git ls-remote backup refs/heads/main` ثبت و در worklog/پیام نهایی اعلام می‌شوند (hook موجود push خودکار را انجام می‌دهد؛ انسان فقط راستی‌آزمایی می‌کند).

- الگوی بررسی: `git diff` (فقط مسیرهای مجاز §۳) → commit مستقل → تأیید اجرای hook (`/tmp/devhook.log` → auto-push OK) → `git rev-parse HEAD` ↔ `git ls-remote backup main` — مقایسهٔ دقیق SHA محلی/Remote در پیام نهایی گزارش می‌شود؛ در صورت شکست push، وضعیت صادقانه اعلام خواهد شد.
- ممنوع‌عات رعایت شد: صفر reset/rebase/force-push/تغییر hook/دست‌کاری `db/custom.db`/cron یا automation جدید.
