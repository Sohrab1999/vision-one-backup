## ۳) طرح آزمون محدود پیشرفت یادگیری (مرحلهٔ ۴ — فقط پس از PASS کامل گِیت)

- دادهٔ مصنوعی با شناسهٔ یکتای همین اجرا (`run-<timestamp>`): یک `User` ساختگی (`username = qa-n155-<ts>`، `pinHash` ساختگی غیرمعتبر عمداً مثل `qa-salt:qa-hash` — هرگز credential واقعی) + دو ردیف `Progress` با کلیدهای واقعی‌نما (مثل `visionone:book:grade-11:learned` و `visionone:book:grade-11:results`) و مقدارهای ساختگی حاوی برچسب run.
- W1 (ثبت + بازخوانی + idempotency): create کاربر و ردیف‌ها → خواندن مستقل با شرط userId → مقایسهٔ مقدارها → **تکرار همان create** با چشم‌بسته نبودن چشم: ثبت رفتار واقعی قید `@@unique([userId, key])` (انتظار: خطای P2002؛ هر رفتار دیگری هم صرفاً ثبت می‌شود).
- W2 (پایداری): فرایند/اتصال کاملاً تازه → بازخوانی همان رکوردها → تطبیق مقدارها (اثبات ماندگاری روی دیسک، نه فقط حافظهٔ اتصال).
- W3 (پاک‌سازی محدود): حذف فقط ردیف‌های ساختگی همین run از **کپی** (Progress سپس User؛ Cascade نیز فعال است) + اثبات بازگشت شمارش‌ها به خط پایه.
- پایان: `sha256sum` اصلی (t2) — اگر ≠ t0 → توقف + گزارش رخداد؛ هیچ ترمیم خودکاری.
- **ممنوع در کل گام:** `prisma db push`، migration، seed، backfill — کپی، schema را از خود اصلی به ارث می‌برد و نیازی به هیچ‌کدام نیست؛ اگر در اجرا مشخص شود چیزی ضروری است، پیش از هر اقدام، تصمیم + مجوز جداگانه گرفته می‌شود.
